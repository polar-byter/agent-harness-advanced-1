## Как устроена модель внутри процесса?

Когда вы пользуетесь ChatGPT или Ollama, нейросеть работает как отдельная удалённая программа. Вы отправляете ей сетевой запрос по HTTP, ждёте ответ и парсите его.

В этом уроке мы поступаем иначе:
1. Мы используем библиотеку **`llama-cpp-python`** - это высокопроизводительный движок на C++, скомпилированный специально для запуска нейросетей на обычных процессорах с инструкциями AVX2.
2. Файл нейросети загружается **прямо в оперативную память вашего скрипта Python**.
3. Обращение к модели происходит не через сеть, а прямым вызовом функции в коде: `model.create_chat_completion(...)`.

### Что такое формат GGUF и квантование (сжатие)?
Файл модели хранится в формате **GGUF** (GPT-Generated Unified Format). Внутри него зашиты веса нейросети - около 1,7 миллиарда чисел, определяющих всё, чему модель научилась при тренировке.

В исходном виде такие веса занимают колоссальный объём памяти (16 бит на каждое число). Но разработчики научились сжимать их - этот процесс называется **квантованием (quantization)**:
* Числа округляют до 8 бит (вариант **Q8_0**) или до 4 бит (вариант **Q4_K_M**).
* Это похоже на сжатие несжатого звука WAV в качественный MP3: размер файла уменьшается в 2-4 раза (модель весит всего 1,8 ГБ вместо 7 ГБ!), а качество ответов для человека остаётся практически неотличимым.

В качестве рабочей лошадки нашего курса мы используем отличную современную модель **Qwen3-1.7B** в варианте Q8_0 из официального репозитория команды Alibaba. На обычном ноутбуке ответ на короткий вопрос занимает всего 1-3 секунды.

## 3. Секретное оружие локального ИИ: Генерация строго по схеме JSON

В первой части курса мы просили модель: *"Ответь в формате JSON"*. Но нейросети коварны: они могут случайно добавить в начало вежливое "Конечно! Вот ваш ответ:", забыть закрывающую кавычку или скобку, и функция `json.loads()` упадет с ошибкой.

У локального движка `llama-cpp-python` есть фантастическая возможность, которой нет у большинства веб-сервисов - **грамматически ограниченное декодирование (Grammar-Constrained Decoding)**:

Мы передаём движку строгую схему допустимого ответа:

```python
DAYS_SCHEMA = {
    'type': 'object',
    'properties': {
        'days': {'type': 'integer'}
    },
    'required': ['days']
}
```

Что происходит под капотом движка?
Когда нейросеть предсказывает каждый следующий токен (букву или слово), C++ движок на лету фильтрует словарь: **он физически блокирует любые токены, которые нарушают формат JSON**!
* Модель не может написать букву вместо цифры в поле `days`.
* Модель не может написать вступительное слово.
* Ответ **всегда** будет стопроцентно валидным JSON: `{"days": 14}`.

## 4. Напишите код сами: главная функция `ask`

Откройте файл `local_llm.py` и найдите функцию `ask`:

```python
def ask(model, instruction: str, text: str, schema: dict | None = None, max_tokens: int = 256):
    settings = dict(SAMPLING, max_tokens=max_tokens)
    if schema is not None:
        settings['response_format'] = {'type': 'json_object', 'schema': schema}
    raise NotImplementedError('Допишите ask в local_llm.py по подсказкам урока 1')
```

Замените строчку `raise NotImplementedError(...)` следующим кодом и заполните два пропуска `...`:

```python
    messages = [
        {'role': 'system', 'content': instruction + NO_THINK},
        {'role': 'user', 'content': ...},
    ]
    response = model.create_chat_completion(messages=..., **settings)
    answer = clean_answer(response)
    if schema is not None:
        return json.loads(answer)
    return answer
```

1. В сообщении с ролью `'user'` передайте входящую переменную: `text`.
2. В метод `model.create_chat_completion` передайте наш список сообщений: `messages=messages`.
3. Функция `clean_answer` автоматически достанет текст ответа и очистит служебные теги.
4. Если была задана `schema`, функция распарсит строку через `json.loads(answer)` и вернёт готовый словарь Python с числом, а не просто текст!

### Анатомия управления памятью: почему используется `@contextmanager`?

В `local_llm.py` модель загружается через контекстный менеджер:

```python
@contextmanager
def load_chat(name: str | None = None, n_ctx: int = 4096):
    path = require(name or chat_model_name())
    from llama_cpp import Llama
    model = Llama(model_path=str(path), n_ctx=n_ctx, n_gpu_layers=0, verbose=False)
    try:
        yield model
    finally:
        model.close()
```

Зачем это нужно?
Файл модели занимает почти 2 гигабайта оперативной памяти. Если загрузить модель как глобальную переменную и забыть освободить память, ваш ноутбук быстро исчерпает ресурсы.

Конструкция `try ... finally: model.close()` гарантирует: как только блок `with load_chat() as model:` завершился (или если внутри произошла ошибка), память C++ движка **будет немедленно и полностью освобождена**.
