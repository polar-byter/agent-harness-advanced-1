# Дополнительно: Как устроен photo_check.py

> **Для кого этот материал:** В Уроке 4 мы научили программу анализировать фотографии бракованных товаров. 
> 
> Здесь мы построчно разберем модуль `photo_check.py`: как кодировать картинку в Base64, как устроен мультимодальный промпт и как программа направляет заявку сотруднику.

---

## 1. Кодирование изображения: image_to_data_uri

```python
import base64
from pathlib import Path

def image_to_data_uri(path: Path) -> str:
    raw_bytes = path.read_bytes()
    encoded = base64.b64encode(raw_bytes).decode('ascii')
    return f'data:image/jpeg;base64,{encoded}'
```
1. `path.read_bytes()`: считывает бинарное содержимое JPEG-файла в память.
2. `base64.b64encode(...)`: преобразует бинарные байты в безопасную текстовую строку из латинских букв и цифр.
3. Префикс `data:image/jpeg;base64,` сообщает C++ проектору модели формат входящих данных (MIME-тип). Картинка передается прямо внутри текстового протокола без сохранения на диск или загрузки на внешние серверы.

## 2. Схема PHOTO_SCHEMA и правило PHOTO_RULE

```python
PHOTO_SCHEMA = {
    'type': 'object',
    'properties': {
        'item': {'type': 'string', 'maxLength': 40},
        'same_item': {'type': 'boolean'},
        'damage_visible': {'type': 'boolean'},
        'comment': {'type': 'string', 'maxLength': 200},
    },
    'required': ['item', 'same_item', 'damage_visible', 'comment'],
}
```

### Почему именно такой порядок полей?
* Авторегрессионные языковые модели генерируют токены строго слева направо.
* Когда поле `item` стоит первым, модель обязана сначала сгенерировать короткое название предмета (например, `"кружка"`).
* Когда модель переходит ко второму полю `same_item`, в ее контексте уже есть слово `"кружка"`, и ей в разы проще сравнить ее с заказанным товаром (`"кроссовки"` -> `false`).
* Если бы поле `same_item` стояло первым, модель часто гадала бы наугад.

## 3. Бизнес-логика маршрутизации: route_return

```python
def route_return(decision: dict) -> str:
    if not decision['same_item']:
        return 'попросить другое фото: на снимке не заказанный товар'
    if decision['damage_visible']:
        return 'сотруднику: на фото видно повреждение'
    return 'сотруднику: на фото повреждений не видно, нужна проверка товара'
```
* Программа опирается **только на жесткие булевы флаги** (`same_item` и `damage_visible`).
* Текстовый комментарий `comment` идет человеку исключительно как справочная подсказка.
* Программа не принимает необратимых финансовых решений самостоятельно: при наличии повреждения заявка эскалируется сотруднику для финальной выплаты.
