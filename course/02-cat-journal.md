# Урок 2. Журнал проделок кота: Настольное приложение с окном и Excel

[Исходники урока](../exercises/lesson-02-cat-journal/README.md) / [Подсказки рядом с кодом](../exercises/lesson-02-cat-journal/TASK.md)

> **Где мы находимся:** Собираем наше первое полноценное десктопное приложение с графическим интерфейсом!
> 
> Программа открывает файл Excel, считывает строки семейного журнала, локальная модель классифицирует каждую запись по строгому списку категорий и шкале серьезности, а затем пишет итоговую сводку и сохраняет отчет обратно в Excel:
> 
> `Файл Excel -> чтение (openpyxl) -> [classify_entry со схемой JSON] -> сводка -> новый лист Excel`

---

## В чем практический смысл задачи?

Представьте семью, у которой живет кот Барсик. Чтобы не спорить, кто виноват в разбитой чашке или опрокинутом цветке, семья завела в Excel журнал: дата, автор записи и что произошло. За неделю накопилось 12 записей - от украденной со стола котлеты до ночного концерта под дверью в три часа ночи. 

Семья хочет нажать одну кнопку и получить:
1. Автоматическую разметку каждой записи по категориям ("кухня", "шум", "порча вещей", "нежности", "охота").
2. Оценку серьезности инцидента от 1 до 3.
3. Короткую текстовую сводку в духе вечерних новостей для семейного чата.

Пример шуточный, но механика - на 100% боевая. Именно так аналитики крупных компаний (например, Авито) размечают тысячи обращений в службу поддержки: модель раскладывает сырой текст клиентов по заданным категориям, а люди анализируют готовую статистику. На примере кота эту механику очень легко освоить: данных немного, ситуации жизненные, и любая ошибка модели видна сразу.

## Категории и секрет точности: почему описания важнее названий

Откройте `journal_ai.py`. В начале файла задан словарь допустимых категорий:

```python
CATEGORIES = {
    'кухня': 'утащил или пытался утащить еду',
    'порча': 'испортил вещь: порвал, разбил, уронил, испачкал',
    'шум': 'мешал спать, громко орал, будил',
    'нежности': 'ласкался, мурлыкал, спал рядом',
    'охота': 'ловил насекомых, птиц, игрушки, гонялся за чем-то',
}
```

Обратите внимание: мы передаем модели не просто сухие слова "кухня", "шум", а даем **четкие пояснения человеческим языком**.

Почему это важно?
В экспериментах при подготовке курса Qwen3 по одним лишь названиям категорий верно определила только 5 записей из 12. А когда к категориям добавили пояснения - модель верно классифицировала 10 из 12! Составление точных пояснений к категориям - это ключевая задача аналитика, а не программиста.

## Напишите код сами

В файле `journal_ai.py` найдите функцию `classify_entry`:

```python
def classify_entry(model, text: str) -> dict:
    if not text.strip():
        raise ValueError('Запись не должна быть пустой')
    raise NotImplementedError('Допишите classify_entry по подсказкам урока')
```

Замените строчку `raise NotImplementedError(...)` следующим кодом и заполните два пропуска `...`:

```python
    schema = {
        'type': 'object',
        'properties': {
            'category': {'type': 'string', 'enum': ...},
            'severity': {'type': 'integer', 'enum': [1, 2, 3]},
        },
        'required': ['category', 'severity'],
    }
    answer = ask(model, CLASSIFY_RULE, ..., schema=schema, max_tokens=64)
    return {'category': answer['category'], 'severity': answer['severity']}
```

1. В ключе `'enum'` для поля `category` укажите список ключей словаря: `list(CATEGORIES)`. Это превратится в список `['кухня', 'порча', 'шум', 'нежности', 'охота']`.
2. Третьим аргументом в функцию `ask` передайте текст входящей записи: `text`.

### Как это работает:
Ключевое слово `'enum'` в схеме JSON жестко ограничивает выбор нейросети. C++ движок разрешит модели выбрать только одно из пяти указанных слов. Модель физически не сможет придумать категорию "еда" или "разбой" - схема гарантирует стопроцентное попадание в рамки!

## Под капотом: как устроен проект урока и ключевые модули

Давайте разберем архитектурные секреты, которые позволяют этому приложению работать плавно и надежно.

### Разделение по слоям (Layered Architecture)
Код разделен строго по ролям:
* `journal_io.py` умеет только читать и писать `.xlsx`. Он ничего не знает про нейросети и кнопки.
* `journal_ai.py` содержит чистую логику работы с моделью. Он не знает, откуда берутся строки - из Excel, веб-формы или Telegram.
* `app.py` отвечает только за отрисовку интерфейса.

Благодаря этому логику классификации можно протестировать юнит-тестами без запуска графического окна.

### Почему графическое окно не зависает во время работы модели?
Инференс модели на процессоре занимает 15-25 секунд на 12 записей. 

В простых скриптах новички вызывают тяжелый код прямо внутри обработчика клика кнопки. В результате окно Tkinter "намертво зависает": операционная система пишет "Программа не отвечает", колесико мыши крутится, интерфейс не перерисовывается.

В `app.py` эта проблема решена профессиональным паттерном:
1. Обработчик клика запускает тяжелую работу в отдельном фоновом потоке: `threading.Thread(target=worker).start()`.
2. Фоновый поток общается с окном через потокобезопасную очередь: `queue.Queue()`. По мере обработки каждой строки он бросает в очередь сообщение о прогрессе.
3. Главное окно раз в 100 миллисекунд опрашивает очередь через таймер `window.after(100, check_queue)` и плавно обновляет таблицу прямо на глазах у пользователя, не блокируя интерфейс ни на миллисекунду!
